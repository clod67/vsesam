# VSËSAM

**Игровой движок на Rust + собственный эзотерический язык `nanch`, AI-агенты, 67-слойное шифрование, MCP-сервер и логин по сессии Claude Code / Codex.**

> _A from-scratch Rust game engine driven by the `nanch` scripting language —
> Chinese + Arabic keywords, `؛` statement terminators — with built-in AI
> agents, 67-layer script encryption, a real MCP server, an AST auto-commenter,
> and login by your coding-assistant session. Zero dependencies, fully offline._

Ноль сторонних зависимостей — только `std`. Язык, ECS, рендер, AI-мозги,
SHA-256, шифратор, JSON-парсер, MCP-сервер и хранилище сессий написаны руками.
**Ни одного сетевого вызова во всём движке** — всё локально.

```sh
cargo build --release
B=./target/release/vsesam

# вход: обычный аккаунт…
```

## Язык `nanch`

Нарочито чужеродный: выражения завершаются арабской `؛` (U+061B), комментарии с
`؟` (U+061F), ключевые слова — иероглифы (+ арабский глагол цикла). Остальное
(`喊`, `生`, `脑` …) — обычные идентификаторы, резолвятся в нативы движка.

| nanch | значение | nanch | значение |
|-------|----------|-------|----------|
| `设` | объявить | `طالما` | while |
| `函` | функция | `真`/`假` | true/false |
| `回` | вернуть | `空` | nil |
| `如果`/`否则` | if/else | | |

Операторы: `+ - * / %`, `== != < > <= >=`, `&& || !`, `=`. Строки `"…"`, числа — `f64`.

```nanch
函 знак(a, b) {
  如果 (b > a) { 回 1؛ }
  如果 (b < a) { 回 -1؛ }
  回 0؛
}
函 охотник(id) {                     ؟ мозг-агент: движок зовёт каждый тик
  设 цель = 近(id)؛                  ؟ ближайший враг
  如果 (цель == 空) { 回؛ }
  动(id, знак(横(id), 横(цель)), знак(纵(id), 纵(цель)))؛
}
设 a = 代理("agent", 10, 5, охотник)؛  ؟ агент с мозгом-функцией
生("goblin", 40, 15)؛
```

**Нативы (мост язык↔движок):** `喊` печать · `字`/`数值` конвертация · `生`/`代理`/`毁`
спавн/агент/уничтожить · `动` двигать · `血`/`满血`/`治`/`伤` здоровье · `阵`/`设阵`
фракция · `名`/`标`/`活` · `近`/`谁`/`距`/`横`/`纵` запросы · `数量`/`敌数`/`友数`/`时`
счётчики · `脑` мозг · `数`/`底`/`绝`/`根`/`最小`/`最大` математика · `记`/`取`/`我` сессия.

## Движок и AI-агенты

ECS-lite: сущности — плоские записи компонентов. Каждый тик: глобальный хук
`每拍` → мозги-агенты → встроенные поведения → движение → бой → уборка. Рендер —
ASCII-грид в рамке (работает headless).

**Два вида AI-агентов:**
1. **Встроенные мозги** (`脑(id, "think")`): `idle/wander/seek/flee/patrol/hunt` +
   флагман `think` (утилитарный AI: ранен→беги, враг в упор→бей, видишь→догоняй).
2. **Мозги на nanch** (`脑(id, функция)`): любая функция `f(id)` = автономный агент.
3. **Внешний AI через MCP** (см. ниже): живая модель рулит миром снаружи.

## 🔒 Шифрование (VSESAM Vault, 67 слоёв)

`seal` прогоняет исходник через **67 раундов** (потоковый XOR в режиме счётчика
на SHA-256 + ключезависимый сдвиг буфера). Ключ по умолчанию — **токен твоей
сессии**, поэтому «код открывается твоим логином».

```sh
vsesam seal script.nanch           # -> script.nanch.vault (ключ: сессия)
vsesam seal script.nanch --pass X  # или своим паролём
vsesam open script.nanch.vault     # расшифровать (нужна верная сессия/пароль)
vsesam run  script.nanch.vault     # расшифровка на лету + запуск
```

**Фримиум-просмотр** — `vsesam view <vault>`: первая строка видна бесплатно,
остальное заперто `▓▓▓`. Разблокировка — `open` со своей сессией.

> ⚠️ Это **игрушечный** шифр для своих скриптов, а не боевая криптография.
> Обратимость и устойчивость к неверному ключу покрыты тестами.

## 🔌 MCP-сервер

`vsesam mcp` поднимает **MCP-сервер** (JSON-RPC 2.0 по stdio) — внешний AI
(Claude, Codex…) может рулить движком как инструментами:

`vsesam_eval` · `vsesam_spawn` · `vsesam_tick` · `vsesam_frame` · `vsesam_stats`
· `vsesam_reset` · `vsesam_annotate` · `vsesam_seal`.

Пример клиентского конфига (stdio):
```json
{ "mcpServers": { "vsesam": { "command": "/path/to/vsesam", "args": ["mcp"] } } }
```
Протокол `2024-11-05`: `initialize` → `tools/list` → `tools/call`. Транспорт
только stdio, без сети.

## 💬 Авто-комментатор и форматтер

`vsesam annotate <script>` разбирает код в AST и ставит `؟`-комментарий перед
каждой инструкцией верхнего уровня — смысл читается из дерева, **не вайбкод**:

```nanch
؟ `g` ← спавнит сущность → id
设 g = 生("goblin", 5, 5)؛
؟ назначает AI-мозг сущности
脑(g, "think")؛
```

`vsesam fmt <script>` — pretty-printer с корректными приоритетами (без лишних скобок).

## 🔑 Логин по сессии Claude Code / Codex (SSO)

`vsesam sso` входит по сессии твоего кодового ассистента. **Важно и намеренно:**
читается только **несекретный** идентификатор из переменных окружения (или явный
`--session`), хешируется **локально** в опаковый аккаунт, хранится только хеш, и
**ничего никуда не отправляется**. Секретные токен-файлы не читаются, выдавать
себя за тебя перед Anthropic/OpenAI движок не умеет. Это SSO по локальной
идентичности, а не кража токенов.

Распознаются: `VSESAM_AI_SESSION` (+`VSESAM_AI_PROVIDER`), `CLAUDE_SESSION_ID` /
`CLAUDECODE`, `CODEX_SESSION_ID` / `OPENAI_SESSION_ID` и т.п. Сессия SSO так же
хранит ключи `记`/`取`, которые встраиваются в движок между запусками.

## Сессии, встроенные в движок

Токен сессии выводится **детерминированно** из аккаунта/идентичности → повторный
вход цепляет **то же** постоянное хранилище ключ-значение. Оно доступно из nanch
через `记`/`取`, так что прогресс игрока (счёт, волна, инвентарь) **захватывается
и встраивается прямо в работающий движок** и переживает перезапуски. Гостевая
сессия не пишется на диск.

```nanch
设 wave = 数值(取("wave"))؛        ؟ прочитать прошлую волну из сессии
如果 (wave == 空) { wave = 1؛ }
记("wave", wave + 1)؛              ؟ сохранить следующую — встроится при выходе
```
